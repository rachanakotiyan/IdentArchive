# IdentArchive – Database Schema (MySQL 8.0.16+, InnoDB, utf8mb4_unicode_ci)

Scripts: `database/scripts/001_create_schema.sql` (create) and `001_rollback.sql` (drop all).
All timestamps are DATETIME in **UTC**; the app's connection pool must set `time_zone: '+00:00'`.

## Tables (creation order)
| Table | Purpose | Key constraints |
|---|---|---|
| users | Accounts (individual / officer / admin) | PK user_id CHAR(36); UNIQUE email (case-insensitive) |
| officers | Staff profile, 1:1 with a user | UNIQUE user_id, UNIQUE badge; FK user_id ON DELETE CASCADE |
| pincodes | Lookup for city/district/state | PK pincode |
| cases | Official case files | UNIQUE case_number, UNIQUE seq, UNIQUE (case_id, kind); CHECK age 0–130, height 20–300; FULLTEXT search |
| case_updates | Public milestones | FK case_id CASCADE |
| reports | Intake reports (login required) | reporter_id NOT NULL FK; UNIQUE reference_no; UNIQUE case_id (one case per report); FK officer SET NULL, FK case SET NULL |
| report_history | Audit trail of status changes | FK report CASCADE; FK actor SET NULL |
| matches | Candidate missing↔found links | UNIQUE (missing_case_id, found_case_id); CHECK score 0–1; composite FKs force missing side = 'missing' case and found side = 'found' case |
| match_verifications | Officer decisions | FK match CASCADE; FK officer (RESTRICT) |

## Changes from the original design (and why)
1. All primary keys that were `VARCHAR(50)` ids are now `CHAR(36)` UUIDs generated by the app (no sequential-id collisions).
2. `reports` and `cases` have a hidden `seq` AUTO_INCREMENT used to build `reference_no` / `case_number`.
   Repository rule: INSERT with `reference_no = report_id` (placeholder), then UPDATE to the final
   `REF-YYYYMMDD-<seq padded 6>` / `IA-YYYY-<seq padded 4>` in the **same transaction**.
3. `officers.name` removed (duplicate of `users.name`; read it by JOIN).
4. `TIMESTAMP` → `DATETIME` (UTC) to avoid the 2038 limit.
5. `cases.crime_type` is an ENUM of the six agreed values.
6. `matches` has two constant columns (`missing_kind`, `found_kind`) so the DB itself rejects a match whose sides are the wrong kind – no triggers needed.
7. Added indexes for status, location, event date, FKs and a FULLTEXT index on cases for public search.

## Rules enforced by the app, not the database
- `officers.user_id` must belong to a user whose role is `officer`/`admin`.
- Approving a report (create case, link `reports.case_id`, write history) happens in one transaction.
- `matches.status` follows the latest verification decision.
- Public queries must never select reporter_*, assigned_officer_id or review_note.
- The app DB user has SELECT/INSERT/UPDATE/DELETE only; migrations use `identarchive_migrate`.
